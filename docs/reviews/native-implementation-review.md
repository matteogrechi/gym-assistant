## Scope and implementation

The [revision-34 specification](../product/spec.md) preceded code and authorizes native persistence, immediate qualifying working-set history and user-supplied local video. The [Android plan](../architecture/android-implementation-plan.md) separates pure [domain rules](../../android/domain/src/main/kotlin/it/matteogrechi/gymassystant/domain/Training.kt) from native Compose features and shared [controls](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/ui/GymComponents.kt)/[theme](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/ui/GymTheme.kt). The [Android README](../../android/README.md) describes build/install and runtime boundaries. Delivery is **debug APK 0.1.0 for local installation only; no public release**.

[Room](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/data/GymDatabase.kt) holds one versioned dataset row and a durable backup revision; [DatasetRepository](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/data/DatasetRepository.kt) serializes committed changes. Plans/drafts, dated original prescriptions, order, nullable actuals, setup, attendance and timers have separate [models](../../android/domain/src/main/kotlin/it/matteogrechi/gymassystant/domain/Models.kt). [Metrics](../../android/domain/src/main/kotlin/it/matteogrechi/gymassystant/domain/Metrics.kt) include qualifying completed working sets immediately, remove undone sets from performance, retain first attendance and preserve missing comparisons. [Timers](../../android/domain/src/main/kotlin/it/matteogrechi/gymassystant/domain/Timers.kt) use monotonic/boot-aware readings and paused export copies.

[LocalDocuments](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/data/LocalDocuments.kt) validates local providers and copies videos into app-owned storage; [ExerciseVideo](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/feature/ExerciseFeature.kt) uses Media3 file-only playback without autoplay. [PortableFiles](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/data/PortableFiles.kt) and [BackupWorker](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/data/BackupWorker.kt) implement the [version-3 text/media contract](../architecture/native-data-v3.md) and [generation/verification rules](../architecture/native-file-layout.md). A folder failure leaves the private log available. The [source manifest](../../android/app/src/main/AndroidManifest.xml) removes INTERNET explicitly, disables app backup and references cloud-backup exclusion XML. Coordinator parsed debug and release merged manifests: both lack INTERNET and set `allowBackup=false`; actual debug APK `aapt` permission output also lacks INTERNET.

The exercise catalog supports creation only. Definition editing/deletion, extra execution working sets, saved-plan deletion/duplication, Finished reopening/history editing, alerts, cloud/accounts and additional metrics/coaching are excluded. Restore UI and legacy migrations remain pending extensions; the JSON reader verifies backups and does not constitute an import feature. GYM-006 external view-reference strips remain mockup-only.

## Failures and source corrections

Coordinator traced the earlier publication-thread device failure through `TestMonotonicFrameClock.performMeasureAndLayout` → `StateFlow.setValue` → `DatasetRepository.update` on an IO worker thread. The log was committed durably before the failing UI publication. [DatasetRepository](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/data/DatasetRepository.kt) now wraps `load` and `update` StateFlow publication in `withContext(Dispatchers.Main)`, preserving the serialized transaction and IO disk work. The final offline run passed **42 JVM tests and all 3 device tests** with build/lint success: the reported publication-thread regression is **validated closed**.

A subsequent integrity refinement wraps the bounded accepted-update Room commit → Main publication → outbox enqueue in `withContext(NonCancellable)`, preserving disk IO and the serialized mutex so closing a screen cannot cancel publication after a durable commit. The new third native regression, `OfflineWorkflowTest.acceptedEditSurvivesCallerCancellation`, cancels the caller inside a valid theme edit, joins that job, then asserts Room theme DARK and cache equality with the decoded stored dataset. **This accepted-edit cancellation regression passed in the final three-test suite**, providing actual Android/Room evidence for the bounded commit/publication cancellation case.

The subsequent log-test timeout was a test sequencing issue: it clicked the disabled completion control before asynchronous weight persistence, then waited for done. The publication-thread measure/layout failure was absent. `sessionLogsPersistAndExerciseHasNoLifecycleActions` now waits for repository state reps=10/kg=20.5 after commit, asserts the done control enabled, and only then clicks. All original data, lifecycle, recreation and partial-Finish assertions remain. The complete offline three-test rerun passed after this timing correction, validating the test sequence with all original assertions intact.

[BackupWorker](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/data/BackupWorker.kt) now verifies stages before publishing canonical JSON/media, quarantines conflicting unverified bytes, checks raw revision identity before retry reuse, leaves unreadable files untouched, and acknowledges only verified content. Pruning retains two verified complete app generations before deleting older matching JSON. The seven harness regressions exercise these failure paths. A successful actual local provider backup is verified above; provider failures, retries and two-generation retention remain to be checked.

Coordinator/source review identified calendar outset/double-centering/crop and line-height defects, navigation icon placement/64dp indicator width, timer font and teal contrast, surface foreground propagation, modal width/text scrolling and initial Cancel focus. Current fixes are in [TrainFeature](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/feature/TrainFeature.kt), [GymApp](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/feature/GymApp.kt), [ExerciseFeature](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/feature/ExerciseFeature.kt), [GymComponents](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/ui/GymComponents.kt), [GymTheme](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/ui/GymTheme.kt) and [GymDialogs](../../android/app/src/main/kotlin/it/matteogrechi/gymassystant/feature/GymDialogs.kt). Later coordinator patches refined accessible reorder-handle names and calendar ordinal formatting. Cancel requests focus on the next frame. Window/system-bar updates follow theme changes, route changes dismiss the keyboard, and date-only presentation avoids timer-driven screen repaints while clock updates remain lifecycle gated.
